## Main finding

A new precision configuration improved the circuit, but it came from **random
search**, not RO. The experiment provides **no demonstrated RO advantage** in
this family under the declared sampled objective.

| Method | Fully valid selected configurations, out of 10 | Best retained full-model Q*C | Median retained Q*C |
|---|---:|---:|---:|
| RO-V2 | 0 | 1,728,155.55 | 1,728,155.55 |
| RO-auto | 0 | 1,728,155.55 | 1,728,155.55 |
| Random search | 3 | **1,667,594.98** | 1,728,155.55 |
| Differential evolution | 0 | 1,728,155.55 | 1,728,155.55 |

"Retained" means keeping the previously native-verified incumbent when a new
selection fails full-domain validation. Only the global best new configuration
received fresh native verification; the table's other selections were checked
with the exact full-domain integer model.

Each method received exactly 1,024 objective calls for each of ten seeds.
There were 40,960 calls in total and 8,701 distinct decoded configurations.
The frozen training sample contained 1,428 inputs. Repeats counted toward the
budget. All methods received the same incumbent evaluation and validation rule.
No optimizer/core implementation was modified.

Random search beat each RO variant in three paired seeds and tied it in seven.
Each RO variant tied differential evolution in all ten retained outcomes.
All four median retained costs were identical. These are limited empirical
outcomes, not a general ranking of optimizers.

## Why most selections failed

The methods optimized a sampled model of cost and feasibility. Their selected
configurations looked valid on that sample but frequently failed on a small
number of full-domain inputs. For example, configuration (13,17,28,27,28)
failed on just **two of 3,133,452 inputs**.

RO-V2, RO-auto and differential evolution each selected a failing configuration
in all ten runs. Random search did so in seven. This exposes the weakness of
the sampled feasibility objective: stronger minimization of an optimistic
proxy can select an invalid circuit. It does not establish that RO is generally
inferior, nor does it invalidate previously verified circuits.

The failed selections remain in the JSON; they were not silently repaired or
substituted during comparison.

The winning configuration was (14,17,29,27,28), found by random search in seeds
1 and 9. It passed the complete native verifier:

This is **3.5043%** cheaper than the previous candidate and **19.7026%**
cheaper than the original reference. The native score exactly matched the
integer model's predicted full-domain cost to the declared tolerance.
The native verifier completed in 801.90 seconds on this runner.

## Competition prospects and next technical decision

The new cost remains **17.0299 times** the cost of the dated public comparator
in [the public comparison](public-comparison-2026-11-16.md). That comparator was
not rerun by us and is not a live-rank claim. Current evidence still does not
support claiming proximity to a prize.

The next priority is a better feasibility objective: stronger error bounds or
a prospectively specified counterexample-guided validation loop, applied
equally to all methods. Beyond that, reducing live registers and changing
arithmetic/phase architecture matters more than further tuning this fixed
precision family. A new search protocol should retain this negative result
and avoid attributing conventional-search gains to RO.
